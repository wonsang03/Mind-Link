# LoginCommunity Oracle SQL 문서

## 1. 작성 목적

현재 Spring Boot 프로젝트(Mind-Link)의 **로그인/회원가입/커뮤니티** 관련 DB 구조를  
Oracle DB에 그대로 생성할 수 있도록 CREATE TABLE SQL을 정리한 문서입니다.

- 현재 개발/로컬 환경: **H2 In-Memory DB** (`spring.jpa.hibernate.ddl-auto=create-drop`)  
- 운영 목표 환경: **Oracle DB** (12c 이상 권장 — `GENERATED BY DEFAULT AS IDENTITY` 사용)  
- JPA 네이밍 전략: 스프링 부트 기본값 적용 (camelCase → snake_case 자동 변환)

---

## 2. 대상 기능

| 기능 | 관련 Entity | 테이블명 |
|------|------------|---------|
| 로그인 / 회원가입 / 내 정보 조회·수정 | `User`, `UserRole` | `users` |
| 게시글 | `Post` | `posts` |
| 댓글 | `PostComment` | `post_comments` |
| 신고 | `Report` | `reports` |
| 공지사항 | `Notice` | `notices` |
| 첨부파일 (이미지/동영상/URL 링크) | `Attachment` | `attachments` |

> **범위 외:** `diagnosis_results` (자가진단 결과) 테이블은 이 문서에 포함하지 않습니다.

---

## 3. 테이블 관계 요약

```
users     1 : N   posts           (posts.author 는 users.name 문자열 저장 — FK 없음)
users     1 : N   post_comments   (post_comments.author 는 users.name 문자열 저장 — FK 없음)
users     1 : N   reports         (reports.reporter_id → users.id)
posts     1 : N   post_comments   (post_comments.post_id → posts.id, CASCADE DELETE)
posts     1 : N   attachments     (target_type='POST',    target_id=posts.id    — 논리적 관계)
post_comments 1:N attachments     (target_type='COMMENT', target_id=post_comments.id — 논리적 관계)
posts     1 : N   reports         (target_type='POST',    target_id=posts.id    — 논리적 관계)
post_comments 1:N reports         (target_type='COMMENT', target_id=post_comments.id — 논리적 관계)
notices             (독립 Entity — users와 직접 연관 없음)
```

> `posts.author`, `post_comments.author`는 현재 `users.name` 문자열을 직접 저장합니다.  
> 향후 `users.id` FK로 개선 가능 — **추후 확인 필요**.

## 5. Oracle CREATE TABLE SQL

> 테이블 생성 순서: users → posts → post_comments → reports → notices → attachments

```sql
-- ============================================================
-- 1. USERS
-- ============================================================
CREATE TABLE users (
    id          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name        VARCHAR2(50)  NOT NULL,
    email       VARCHAR2(100) NOT NULL,
    password    VARCHAR2(255) NOT NULL,
    role        VARCHAR2(20)  DEFAULT 'USER' NOT NULL,
    created_at  TIMESTAMP     DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT uq_users_email   UNIQUE (email),
    CONSTRAINT chk_users_role   CHECK (role IN ('USER', 'COUNSELOR', 'ADMIN'))
);

-- ============================================================
-- 2. POSTS
-- ============================================================
CREATE TABLE posts (
    id          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    author      VARCHAR2(50)  NOT NULL,
    title       VARCHAR2(200) NOT NULL,
    content     CLOB          NOT NULL,
    category    VARCHAR2(30)  NOT NULL,
    likes       NUMBER(10)    DEFAULT 0 NOT NULL,
    created_at  TIMESTAMP     DEFAULT SYSTIMESTAMP NOT NULL
);

-- ============================================================
-- 3. POST_COMMENTS
-- ============================================================
CREATE TABLE post_comments (
    id          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    post_id     NUMBER        NOT NULL,
    author      VARCHAR2(50)  NOT NULL,
    content     CLOB          NOT NULL,
    created_at  TIMESTAMP     DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT fk_comments_post
        FOREIGN KEY (post_id) REFERENCES posts(id) ON DELETE CASCADE
);

-- ============================================================
-- 4. REPORTS
-- ============================================================
CREATE TABLE reports (
    id          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    reporter_id NUMBER        NOT NULL,
    target_type VARCHAR2(10)  NOT NULL,
    target_id   NUMBER        NOT NULL,
    reason      CLOB          NOT NULL,
    created_at  TIMESTAMP     DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT fk_reports_reporter
        FOREIGN KEY (reporter_id) REFERENCES users(id),
    CONSTRAINT chk_reports_target_type
        CHECK (target_type IN ('POST', 'COMMENT'))
);

-- ============================================================
-- 5. NOTICES
-- ============================================================
CREATE TABLE notices (
    id          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    category    VARCHAR2(30)  NOT NULL,
    title       VARCHAR2(200) NOT NULL,
    summary     VARCHAR2(500) NOT NULL,
    content     CLOB          NOT NULL,
    created_at  TIMESTAMP     DEFAULT SYSTIMESTAMP NOT NULL
);

-- ============================================================
-- 6. ATTACHMENTS
-- ============================================================
CREATE TABLE attachments (
    id                  NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    original_file_name  VARCHAR2(255) NOT NULL,
    stored_file_name    VARCHAR2(255) NOT NULL,
    file_url            VARCHAR2(500) NOT NULL,
    file_type           VARCHAR2(10)  NOT NULL,
    file_size           NUMBER(20)    DEFAULT 0 NOT NULL,
    target_type         VARCHAR2(10)  NOT NULL,
    target_id           NUMBER        NOT NULL,
    created_at          TIMESTAMP     DEFAULT SYSTIMESTAMP NOT NULL,
    CONSTRAINT chk_attachments_file_type
        CHECK (file_type IN ('IMAGE', 'VIDEO', 'LINK')),
    CONSTRAINT chk_attachments_target_type
        CHECK (target_type IN ('POST', 'COMMENT'))
);
```

## 6. 제약조건 및 외래키 요약

| 테이블 | 제약조건 이름 | 종류 | 대상 컬럼 | 참조 |
|--------|-------------|------|----------|------|
| `users` | `uq_users_email` | UNIQUE | `email` | — |
| `users` | `chk_users_role` | CHECK | `role` | 'USER','COUNSELOR','ADMIN' |
| `post_comments` | `fk_comments_post` | FK | `post_id` | `posts(id)` ON DELETE CASCADE |
| `reports` | `fk_reports_reporter` | FK | `reporter_id` | `users(id)` |
| `reports` | `chk_reports_target_type` | CHECK | `target_type` | 'POST','COMMENT' |
| `attachments` | `chk_attachments_file_type` | CHECK | `file_type` | 'IMAGE','VIDEO','LINK' |
| `attachments` | `chk_attachments_target_type` | CHECK | `target_type` | 'POST','COMMENT' |

> `attachments.target_id`와 `reports.target_id`는 논리적 참조 — Oracle FK 없음  
> (게시글/댓글 구분은 `target_type` 컬럼으로 처리)

## 8. DROP TABLE SQL (삭제 순서)

FK 참조 관계로 인해 아래 순서로 DROP해야 합니다.

```sql
-- FK 관계 고려: 참조하는 테이블 먼저 삭제
DROP TABLE attachments    PURGE;
DROP TABLE reports        PURGE;
DROP TABLE post_comments  PURGE;
DROP TABLE notices        PURGE;
DROP TABLE posts          PURGE;
DROP TABLE users          PURGE;
```

> Oracle에서는 `PURGE` 옵션을 붙이면 휴지통(Recycle Bin)을 거치지 않고 즉시 삭제됩니다.  
> 또는 `DROP TABLE ... CASCADE CONSTRAINTS` 옵션으로 FK 제약 무시 후 순서 상관없이 삭제 가능합니다.

## 9. H2 ↔ Oracle 주요 차이점

| 항목 | H2 (현재 로컬) | Oracle (운영 목표) |
|------|--------------|-----------------|
| 자동 증가 PK | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | `NUMBER GENERATED BY DEFAULT AS IDENTITY` (12c+) |
| 긴 문자열 | `TEXT` (`columnDefinition = "TEXT"`) | `CLOB` |
| 문자열 타입 | `VARCHAR` | `VARCHAR2` |
| 현재 시각 기본값 | `NOW()` | `SYSTIMESTAMP` |
| Boolean | `BOOLEAN` | `NUMBER(1)` (0/1) — 추후 확인 필요 |
| 대소문자 구분 | 기본: 대소문자 무시 | 기본: 대소문자 구분 |

## 10. application.properties Oracle 연동 설정 예시

```properties
# Oracle JDBC
spring.datasource.url=jdbc:oracle:thin:@//localhost:1521/ORCL
spring.datasource.driver-class-name=oracle.jdbc.OracleDriver
spring.datasource.username=mindlink
spring.datasource.password=your_password

# JPA — Oracle 방언, DDL 자동 생성 비활성화 (SQL 직접 실행)
spring.jpa.database-platform=org.hibernate.dialect.OracleDialect
spring.jpa.hibernate.ddl-auto=none
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

> `ddl-auto=none`으로 설정하고, 이 문서의 CREATE TABLE SQL을 직접 실행하세요.
