# Mind-Link 보고서 — 양식 자동 작성 프롬프트

**목적**: 과제 PDF/한글에 적힌 **목차·소제목·안내 문구 그대로** 두고, 예시 문단만 **실제 내용으로 바꿔** 전체 보고서를 한 번에 채운다.  
**다른 사람보다 얇게 나온 이유**는 보통 (1) 양식만 짧게 넣음 (2) `@README` `@docs/backend.md` 미첨부 (3) 「짧게」 지시 (4) 예시 아래에 덧붙여 중복만 늘림 — 이 프롬프트는 **분량 하한**과 **코드베이스 필수 참조**로 막는다.

---

## Cursor에서 쓰는 방법 (권장)

1. 새 채팅 → **아래 「전체 자동 작성」 블록** 붙여넣기  
2. 첨부: `@README.md`
3. `[과제 보고서 양식]` 자리에 **과제에 적힌 목차·작성 안내 전체** 복사 (예시 문단 포함돼도 됨)  
4. `[팀 역할표]` · `[목표 쪽수]` 만 채우고 실행  
5. 결과가 얇으면 맨 아래 **「분량 부족 시 재요청」** 문장만 추가해 재실행  
6. 프로젝트를를 통한 API,db,frontend,backend 분석

```
당신은 목포대 웹프로그래밍2 팀 프로젝트 「Mind-Link(마음이음)」 최종 보고서 작성자입니다.
첨부·프로젝트의 README.md, docs/backend.md, sql/README.md, docs/frontend.md를 **반드시 읽고** 사실만 기술하세요.

## 작업 방식 (2단계, 한 번의 응답에 모두 출력)

### 1단계: 양식 파싱
- 사용자가 준 「과제 보고서 양식」에서 **번호·제목·소제목·표 양식**을 그대로 추출해 목차를 만든다.
- 「예시」「샘플」「작성하시오」「～을 기술할 것」은 **쓸 내용의 주제**로만 쓰고, 그 문장 자체는 최종본에 넣지 않는다.

### 2단계: 양식 순서대로 본문 작성
- 양식의 **모든** 장·절·소절을 빠짐없이 채운다. 「생략」「동일」 금지.
- 각 소절은 **예시 문단을 삭제한 뒤 그 자리에** 완성문만 넣는다. 예시 **아래에** 추가하지 않는다.

## 분량 하한 (얇게 쓰지 말 것 — 다른 팀원 AI 출력 수준 목표)

| 구분 | 최소 분량 |
|------|-----------|
| 표지·개요·프로젝트 소개 | 서론 각 8문장 이상 (문제의식, 대상, 목표, 범위, 기대효과) |
| 요구사항 | 표 1개(기능 ID·명칭·우선순위·수용기준) + 기능당 수용기준 2문장 |
| 시스템 구조·설계 | 패키지/레이어 설명 12문장 이상 + **표 2개**(기술스택, 주요 URL) |
| DB 설계 | 테이블 **10개 이상** 행으로 정리(테이블명·용도·주요 컬럼) + SQL 실행 순서 표(sql/01→02→03) |
| 기능 구현 | **기능 8개 이상** 각각: 목적 2문장 + 흐름(Controller→Service→DB/API) 4문장 + 한계 1문장 |
| 화면/UI | 주요 화면 **6개 이상** (경로·역할·입력·출력) |
| 테스트 | 시나리오 표 **8행 이상**(번호·기능·입력·기대·결과·비고) |
| 팀 역할·일정·협업 | 표 1개 + 병합·Git·역할 분담 6문장 |
| 결론·소감 | 각 6문장 이상 (성과·한계·개선·소감) |

전체 목표: **[목표 쪽수, 예: 한글 A4 20~25쪽 분량의 밀도]** — 짧은 개요 1~2문장으로 끝내는 섹션 금지.

## 반드시 넣을 표 (양식에 표 칸이 없어도 해당 절 안에 삽입)

1. **기능 요약표** — 홈, 로그인, 자가진단, 알림, 상담소, 예약, 커뮤니티, 공지, 추천, 케어편지, 관리자, 클러스터(선택)  
2. **REST API 표** — Method, URL, 설명 10행 이상  
3. **Oracle SQL 실행 순서** — sql/README.md 기준  
4. **외부 API 표** — 네이버(지역/도서/이미지), Gemini(추천), OpenAI(편지), 키 이름(.env)  
5. **역할·권한** — USER / COUNSELOR / ADMIN  

## 기능별로 반드시 밝힐 구현 사실 (backend.md·README 기준, 허위 금지)

- 진입점: `com.mindlink.MindLinkApplication`
- 인증: HttpSession, BCrypt, 컨트롤러에서 세션 검사
- 자가진단: PHQ-9, GAD-7, PSS, CBI · `assessment_*` · `AssessmentService` · 결과 `assessment_results` · 알림 연동
- 상담소: `NaverLocalSearchClient` · 지도 mapx/mapy 좌표 우선
- AI 도서: `recommendation` 패키지 · Gemini 3단계 파이프라인 · `POST /api/recommendations/ai`
- 위로 편지: `care` 패키지 · OpenAI · `CareReportService` · PDF · `care_reports`
- 알림: `user_alerts` · 9종 alert_type · `/alerts` · 관리자 발송 `/admin/alerts`
- 관리자: `/admin` 대시보드, 유저, 게시글, 공지, SQL 콘솔, 3D 클러스터
- 커뮤니티: 첨부, YouTube 본문 embed, 답글(`parent_comment_id`)
- 데모/미구현 구분: 예전 키워드-only ai-care vs 실제 OpenAI care-report

## 문체·품질

- 한국어 보고서체(～한다 / ～하였다) 통일
- 추상어만 쓰지 말고 **클래스명·URL·테이블명·SQL 파일명**을 섞어 쓴다
- 같은 문장·같은 표를 두 절에 반복하지 않는다
- 과장(「완벽한 AI」) 금지
```

## 왜 이전보다 적게 나왔을 수 있는지

| 원인 | 해결 |
|------|------|
| 「짧게」「요약해」 지시 | 이 프롬프트의 **분량 하한** 사용 |

## 장이 너무 길 때 (선택)

양식이 10장 이상이면 **장 단위**로 나눠도 된다. 이때 맨 아래에 붙인다:

```
이번에는 양식 중 「3. 시스템 구현」～「3.4」만 작성. 다른 장은 쓰지 마라. 분량 하한은 해당 절에만 1.5배 적용.
```

## 일반 팀플 목차가 없을 때 (양식이 비어 있으면)

아래를 `[과제 보고서 양식]` 대신 넣고 위 「전체 자동 작성」과 함께 사용:

```
1. 프로젝트 개요 (배경, 목적, 범위)
2. 요구사항 분석 (기능·비기능)
3. 시스템 설계 (구조, DB, API)
4. 구현 (기능별)
5. 테스트
6. 팀 구성·역할·개발 일정
7. 결론 및 소감
부록: ERD·화면 캡션 목록
```
